# 隐映 / INKSHIELD — 本地视频隐私遮罩原型

## 工作方式：分析一次，预览与导出分开

1. 导入本地视频只保存素材并读取帧率、尺寸与帧数，**不运行模型推理**。在时间线上定位并分割视频，选中一个片段后点击“一键分析”，才分析该片段的全部七类支持目标。片段采用起始帧包含、结束帧不包含的范围，分割不改变原文件；各片段分别保留配置和缓存。未分析时播放器显示明确标注的原视频。分析/导出期间暂时禁用换素材、切片和切换片段，预览配置仍可在导出期间调整。
2. 分析完成后，多选头部、人脸、眼睛、鼻子、嘴巴、耳朵或车牌，切换马赛克、高斯模糊、黑色色块，调整强度（20–100）。拖动时间线播放头，查看对应时间点与设置的 JPEG 效果快照。
3. 支持两种检查方式：拖动时间线播放头查看后端合成的原分辨率 JPEG；或点击原速播放，以浏览器原视频时钟 1× 连续播放并由 Canvas 绘制缓存遮罩。两者均**不重复模型推理、不先生成整段视频**。播放时读取已有帧遮罩几何，不逐帧请求网络；全素材连续播放会先准备从播放头起途经的已分析片段缓存，片段较多时准备会有等待，可点击“取消准备”停止此次播放准备。选中片段播放时，切换配置直接更新当前画面。浏览器合成预览最长边限制为 960 像素，模糊与采样效果和后端导出不是逐像素一致；原分辨率 JPEG 和导出用于最终检查。播放/暂停与“静音开关”分别控制；静音开关同时作用于工作台预览和下一次导出。点击导出时，静音开启则移除声音，关闭则裁切原素材对应片段音轨并转为 AAC；该次任务固定使用点击时的声音状态，之后切换开关不改变正在导出的文件。无音轨素材仍输出无声视频。实际流畅度受浏览器解码和绘制能力影响，无法保证每一帧都展示；实时钟优先，不通过放慢视频等待绘制。当前帧号按 mediaTime × FPS 映射，仅对恒定帧率视频具有该时序假设，变帧率视频暂不保证精确对齐。
4. 满意后单独点击“导出当前设置的视频”。导出按**点击时的固定配置**处理当前片段的所有帧；此时仍可调整预览，调整不会改变正在导出的文件。界面明确显示该次导出的固定部位、样式与强度。
5. 完成后下载 MP4。修改预览不会修改已导出的文件；需要新配置时再次导出。

浏览器承担界面与播放时的缓存遮罩绘制；本地 FastAPI 服务通过 ONNX Runtime 调用 **DEIMv2-Wholebody34 Pico ONNX + HyperLPR3-320 检测 ONNX**（不加载车牌号码识别网络）。不加载 CDN、在线推理或远程模型，原视频不上传云端。建议通过本机回环地址访问，不要向公网开放这个原型。

## 面板布局

桌面宽度下可拖动素材库与播放器之间、播放器与检查器之间的竖向分隔线，调整左右面板宽度；拖动播放器与时间线之间的横向分隔线，调整上方工作区和底部时间线的高度。各区域设有最小尺寸，窗口缩小时会限制布局，避免把播放器挤没。

布局尺寸保存在当前浏览器本地，刷新后恢复；浏览器禁止本地存储时仍可调整本次布局。顶部“恢复默认布局”可重置尺寸。窄屏采用纵向排列。调整布局不运行检测，也不改变片段、打码参数和分析缓存。

## 时间线操作

底部以整条原视频为统一时间轴：刻度和播放头采用素材的全局时间，片段在视频轨道上按真实时长比例显示，下一行显示对应的打码配置或待分析状态。点击轨道片段或左侧片段列表会明确选中该段；点击时间线刻度或拖动播放头时，自动选中当前帧所在片段，拖过切点同步切换配置与缓存。点击工作台或时间线外侧空白可取消片段选中。

- 在片段内部定位，点击分割或按 **Ctrl+B**，生成连续且不重叠的两段，播放头保留在切点并选中右段。两段继承打码配置，需各自手动分析。
- 点击撤销或按 **Ctrl+Z** 可撤销分割，恢复分割前片段的设置及已有分析缓存，其他片段后续的配置、缓存与导出结果保留。最多保留 50 次分割记录；撤销仅覆盖分割操作。
- 时间线支持 **1–32×** 缩放和水平滚动；鼠标停留时间线时向上滚轮放大、向下缩小，以鼠标所在时间点为锚（素材边缘受滚动边界限制）。Shift+滚轮保留水平滚动，“适应时间线”恢复全览。左右方向键逐帧移动，空格播放或暂停，时间轴聚焦时 Home/End 定位素材首尾。
- **选中片段时**，播放仅在该片段范围内进行，到片段末尾停止。**取消选中后**，播放从当前播放头连续进行至原素材末尾，跨越切点时按各片段自己的配置和缓存合成；未分析的片段显示原视频并明确标注。读取已有轨迹不触发推理，轨迹加载失败时停止并提示。
- 取消选中后，分析、片段参数修改和导出须先点击选中目标片段。播放和定位不会自动启动分析。分析或导出期间禁止切换片段、分割及撤销。

缩放、定位和分割不运行模型。片段和撤销历史保存在当前页面会话内，刷新页面不恢复。

## 支持部位与遮罩

- 支持 head（头部，class 7）、face（人脸，16）、eyes（眼睛，17）、nose（鼻子，18）、mouth（嘴巴，19）、ears（耳朵，20）、plate（车牌，应用本地 class 21，非 Wholebody34 原模型类别）。至少选择一种，可多选。不从头框猜测未检出的器官位置；无跨帧跟踪或漏检补偿。
- 头部、人脸、鼻子、嘴巴、耳朵通常使用检测框内接椭圆。单眼独立遮罩；同一归属框内的双眼，经尺度、距离上限等检查后合成为沿双眼方向旋转的矩形遮罩带。归属使用逐帧头部/人脸检测框的保守启发式，并不是身份识别或同一人保证；归属不明或配对检查不通过时保持独立遮罩，漏检或错误的归属框仍可能造成误配对。请人工检查。
- 尺寸以原检测几何为基准：单眼椭圆和双眼旋转矩形的长、宽均 ×1.2；嘴巴椭圆长、宽均 ×1.2；人脸椭圆仅原始短边 ×1.15（正方形按宽边处理）。保持中心与角度，头部、鼻子、耳朵不变；扩大的几何由单帧预览、连续播放和导出共用，不修改缓存检测框或眼睛归属判断。
- 遮罩边缘相对调整后的形状向内羽化，不再额外向外扩散。**亚像素例外**：如果检测区域内没有任何像素中心获得非零遮罩透明度，则保护性遮盖最近的一个像素；该离散像素可能超出严格的内接区域，不应将“不外扩”理解为对亚像素检测的绝对几何保证。渐变边缘会透出原图，椭圆四角不覆盖，因此外观柔和不等于隐私覆盖完整。
- 样式支持 mosaic（马赛克）、blur（高斯模糊）、black（黑色色块）。强度只调节马赛克颗粒与模糊程度；黑色色块中心不随强度变浅。遮罩宽或高不足 8 像素时，**马赛克和模糊均回退为黑色效果**，保留对应形状与边缘透明度，避免极小区域近似原图；仍须实际检查效果。
- 默认折叠的“高级选项”允许设置下一轮模型推理置信度阈值，范围 **0.05–0.95**，默认 **0.50**。阈值对全部七类生效，每个分析任务冻结该值并写入检测缓存元数据；降低可能增加检出与误检，升高可能漏检。修改后须明确点击重新分析，不会改变已完成缓存或自动重新推理。小部位、运动、侧脸、遮挡可能漏检或抖动，模型就绪与处理完成均不代表隐私安全验收通过。

### 车牌遮罩

HyperLPR3-320 每帧检测一次，只缓存车牌位置与置信度，不识别号码、不加载 OCR/颜色网络。车牌用轴对齐矩形，长宽扩大至检测框的 1.25 倍，配合向内羽化；四角点不是本版遮罩几何，不声称四边形贴合。三种样式、JPEG、连续播放和导出共用此几何。降低统一阈值可能增加误检，两模型的分数未做跨模型概率校准。小车牌、斜拍、夜间、遮挡仍可能漏检；须人工检查。新增模型增加分析耗时，但配置预览/导出仍不推理。当前下载权重实测为 2,343,161 字节（2.23 MiB），不是早期二手资料所说的约 6.8 MB。

本机验证：一张上游 quicktest 样图检出一块车牌，融合分数约 0.922；检测器 CPU4、30 次单帧调用中位 11.11 ms、p95 12.12 ms（不代表持续视频吞吐）。由该图重复生成的 8 帧短片跑通真实双模型分析、三种 JPEG 样式、播放轨迹与车牌导出，完整重解码 8 帧，并数值检查黑块覆盖检出框。缓存预览/导出禁止模型调用测试通过。尚未完成真实浏览器视觉对齐、道路动态/夜间/小牌覆盖验收；当前运行模型不支持图片输入，不能将数值检测等同人工目视检查。

检测权重默认 `models/y5fu_320x_sim.onnx`，可用 `INKSHIELD_PLATE_MODEL` 指定替代路径；部署须同时准备两模型，缺车牌模型会明确报错，不静默忽略车牌。来源、摘要与许可边界见 `models/HYPERLPR_SOURCE.md`。应用运行不联网下载模型。

## Windows EXE

双击单文件 `dist/Inkshield.exe`，内含 CPython、两模型和本地处理依赖；不要求用户安装 Python 或 CUDA。目标 Windows 10/11 x64 Intel/AMD，建议 8GB 以上内存；尚无跨机器验收，不承诺所有电脑性能。桌面窗口使用系统 WebView2；不可用时退回默认浏览器和 Tk 服务控制窗口。程序自动绑定空闲回环端口，关闭窗口停止此次本地服务，运行中的任务会提示确认。

桌面和浏览器回退入口均为本机 `/startup`：播放约 3.2 秒像素眼形动画，再以约 1 秒淡入过渡显示同源工作台。可跳过、加载失败可重试，尊重减少动态效果设置；内置资源无需 8001/8002 预览服务。单文件解压和 Python/WebView2 初始化发生在窗口出现前，不计入动效时长。

冻结程序资源来自 PyInstaller 临时展开目录；用户数据放在 `%LOCALAPPDATA%/Inkshield`（日志 `inkshield.log`，素材/缓存/导出在 `runtime`）。开发模式仍用项目内 `runtime`。可通过环境变量 `INKSHIELD_DATA_DIR` 或桌面参数 `--data-dir` 指定数据目录；`--serve-only --port 0` 用于无窗口诊断。不会自动清理旧数据，也未实现重启恢复。

构建入口 `build_exe.ps1`，资源清单 `inkshield.spec`；完整固定环境在 `requirements-packaging.lock.txt`，依赖与模型授权限制见 `PACKAGING_REPORT.md`。用户说明为 `WINDOWS使用说明.txt`。当前未签名，未内置系统 WebView2/VC++ 安装器；权重独立授权仍需在公开分发/商业发布前确认。

## API 契约

| 请求 | 用途 |
| --- | --- |
| `GET /api/health` | 模型就绪与支持部位、样式信息；首次加载可能较慢。 |
| `POST /api/media` | multipart 上传 `video`，只读取元数据、不调用检测器；返回 `media_id`、`frames`、`fps`、`width`、`height`。 |
| `POST /api/analyze` | multipart 提交 `media_id`（兼容直接上传 `video`），可选 `start_frame`（默认0）、`end_frame`（不包含，默认素材末尾）、`threshold`（0.05–0.95，默认0.50）；只分析选定帧范围内全部支持部位，返回 `job_id`、`status`。 |
| `GET /api/status/{job_id}` | 查询分析或导出任务；界面兼容状态字段 `status` 或 `state`。分析为 queued/loading/analyzing/ready/error，导出为 queued/processing/done/error。 |
| `GET /api/preview/{analysis_id}?frame=0&target=head,eyes&style=mosaic&strength=68` | 分析 ready 后按零起算帧号和所选配置返回 JPEG；不推理。分析期间不承诺 JPEG 可用。 |
| `GET /api/playback/{analysis_id}` | 分析 ready 后一次读取全部帧遮罩几何，JSON shapes 为逐帧 `[kind,cx,cy,rx,ry,angle,class_id]` 列表；角度为弧度，坐标为原图像素。用于浏览器原速播放，不推理。 |
| `POST /api/export/{analysis_id}` | 表单 `target`（逗号分隔，至少一种）、`style`、`strength`、`muted`（布尔，默认 true）；从缓存检测结果合成，返回**新的**导出 `job_id` 与 `status`。 |
| `GET /api/download/{job_id}` | 导出完成后的 MP4 下载；完成状态提供同源 `download` 地址。 |

分析状态提供 `frames`、`width`、`height`、`fps`、`progress`（0–100）、当前处理帧 `frame`；ready 后的有效帧数、帧率用于逐帧滑块。`frames` 和预览 `frame` 为片段内的相对帧数/索引，`start_frame`、`end_frame` 为原素材全局范围，结束帧不包含；播放轨迹同时提供 `start_frame`，浏览器据此定位原视频。预览只提交当前帧与当前配置，不发送新视频。导出状态的 `progress` 同样使用 0–100。

## 前端异步与错误处理

- 分析或导出任务进行时暂时禁用更换素材、切换片段和分割，避免丢失任务归属。空闲时切换片段恢复各自缓存、配置与下载链接。更换素材使旧请求代际失效，不删除后端数据。**浏览器取消请求并不取消已经提交的后端任务**。
- 点击一键分析打开进度弹窗，可关闭后继续处理；工作台保留明显的进度入口，可重新打开弹窗。关闭弹窗不取消后端任务。分割后生成的新片段需要手动分析，旧片段缓存不被冒用。
- 当前导出选中的片段，未提供多段自动拼接成一个文件。片段及界面配置保存在当前页面会话内，刷新页面不恢复；后端原视频、缓存与输出仍保留。
- 状态查询串行进行：上次完成后等待 600 ms 再查；失败最多连续重试两次，每次间隔 1500 ms。单次查询超时 30 秒，分析上传超时 120 秒；分析、导出状态查询各有两小时总时限。持续失败后停止查询并提示后台可能仍在运行，应确认服务状态后再重试。
- 分析完成前禁用效果参数、帧滑块与导出；ready 后允许参数和帧预览。导出只禁用重复导出按钮，不锁定预览设置。
- 播放中修改部位、样式或强度时直接重绘 Canvas，不逐帧请求网络。拖动时间线播放头会暂停播放，切回精确 JPEG 检查；非播放状态的参数与帧修改立即使旧快照失效，经过 140 ms 防抖请求新 JPEG；使用 AbortController、文件代际和预览代际检查，避免旧响应覆盖新设置。JPEG 下载及图像解码成功后才展示；失败显示明确提示，不把原视频误标为已遮罩效果。
- 分析失败提供重试分析按钮；更换文件可开始新分析。导出完成后仍显示可调整的 JPEG 预览，不自动切到输出视频，避免已冻结导出配置与当前设置混淆。

## CPU 分析性能

- 自动配置：逻辑处理器不少于 12 个时，人体模型使用最多 8 线程，车牌模型最多 2 线程，同一帧的两模型并行执行，并关闭 ORT 空闲自旋。较小 CPU 保留原有最多 4 线程的串行流程；线程数规则是默认策略，不代表所有 CPU 都实测更快。启动前可用 `INKSHIELD_CPU_MODE=serial` 恢复原串行配置，或用 `parallel` 显式启用并行，默认值为 `auto`。
- 每次最多一个分析任务运行、一个帧内车牌任务在途；两个模型完成后才发布这一帧。任一检测失败不会发布完整缓存，退出时等待在途工作结束。仍逐帧运行全部七类，模型、分辨率、精度和阈值规则保持原有设置。
- Ryzen 7 7435H（8 核／16 逻辑处理器），ORT 1.23.2，三个既有真实样本帧，ABBA 顺序复测，每轮 24 次：原配置中位 115.613 / 116.601 ms，优化配置 101.079 / 99.615 ms；平均中位延迟减少 13.6%。原配置 p95 125.083 / 124.343 ms，优化配置 109.354 / 105.244 ms。原/新输出类别数量一致，坐标误差不超过 0.05 像素，分数误差不超过 1e-5。报告为 `runtime/inference-confirmation.json`，复测入口 `benchmark_inference.py --confirm`。这是已解码帧的检测性能，不包含加载、解码、缓存和导出，也不代表持续长视频或隐私覆盖验收。
- 分段起点前采用顺序 `grab()` 跳帧，保留帧间解码依赖，省去无用的 BGR 转换。现有源视频跳过 100 帧的五次测试中位耗时从 227.58 ms 降至 119.79 ms，随后读取帧的像素完全相同；仍随分段起点增长，未采用不精确的随机定位。
- 分析完成状态提供 `analysis_fps`、`cpu_mode`、`timing_ms`（排队、准备、解码、人体、车牌和检测墙钟耗时）。并行时两模型各自耗时重叠，不能相加当成检测墙钟时间。

## 存储、资源与隐私边界

- **上传原视频、检测结果缓存和导出 MP4 保留在本机 `runtime` 下，不自动删除。** 本地处理不等于不落盘；敏感测试后请自行确认并清理，先停止仍在使用这些文件的任务。更换前端文件不会删除后端数据，也不会取消已提交任务。
- 任务在当前服务进程内管理；不要依赖服务重启后仍能通过旧任务 ID 查询或恢复。
- 应用层限制：单次上传 512 MiB、18,000 帧、同时两个分析/导出任务；图像上限 8,294,400 像素且单边不超过 8192。预览合成同时最多两个请求，忙时返回 429，可稍后调整参数重试。上传大小限制位于 multipart 解析之后，并非网络入口流量或临时磁盘的硬配额；仅供本机使用，不要公开部署。
- 缓存检测结果避免因换参数重复推理，但不代表无限视频长度、并发任务或磁盘空间均可承受。先用短片确认资源、速度与遮罩效果，不把原型当作生产级任务队列。
- 输出使用 OpenCV **mp4v**，**不保留原始音频**；不承诺保留全部原始容器元数据。浏览器对该编码的支持不同，不能播放不等于文件未生成，可下载后用支持该编码的本地播放器检查。
- 不保证检出所有人、所有部位或正确匹配所有双眼。未检出的帧不代表没有敏感部位；轻度模糊、马赛克与羽化边缘也不保证去除可识别信息。正式发布前须逐段检查整个导出文件，必要时使用更保守遮挡方案。

## 验收建议

以实际视频分别检查：导入后不推理；分割后两段边界连续、互不重叠；选中片段点击一键分析才执行一轮全部部位分析；关闭进度弹窗后顶部进度仍更新、可重新打开；切换片段后恢复各自设置和缓存；ready 前不请求效果 JPEG；ready 后切换全部七部位、三样式和强度，拖动不同帧无需等待重新推理；双眼旋转矩形与独眼独立效果；快速拖动/换参数/换文件不串帧；导出期间继续预览，下载仍对应点击时的冻结配置；导出可解码、帧数正确，分别核对静音和保留声音的片段范围与音画时长。语法检查或模型健康检查不能代替浏览器端到端验收与隐私效果检查。
