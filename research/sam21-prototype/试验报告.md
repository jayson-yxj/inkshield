# SAM 2.1 点击目标打码试验

本次独立原型已接入官方 SAM 2.1 tiny CPU 视频预测器；正式隐映时间线版未修改，SAM 3未接入。

## 实现范围

单目标；逐帧正点和负点；多个提示帧；向前/向后完整传播；补点重新计算；青色掩码叠加及实际打码预览；马赛克/高斯模糊/黑块导出；原始像素点击坐标；向外扩张掩码。每个提示帧必须至少一个正点。任意帧掩码为空时，界面与API均禁止导出。

输入最高1280×720、宽高偶数、256MB、前150帧；输出无声。不是正式EXE集成，不支持自然语言和多目标。输入帧数可知时会核对实际解码提前终止；帧数未知的容器无法可靠区分解码器失败和正常结束。

## 真实模型及接口验证

- 官方代码固定提交2b90b9f5ceec907a1c18123530e92e794ad901a4，官方权重156008466字节，SHA256 7402e0d864fa82708a20fbd15bc84245c2f26dff0eb43a4b5b93452deb34be69；代码和权重Apache 2.0。来源证据见 ENGINE_SETUP.md、models/provenance.json。
- CPU 4线程，640×360真实5帧，中间帧开始前后传播：模型首次加载5.35秒，分割28.04秒（5.61秒/帧），两提示帧重算33.86秒；全部帧掩码为二值且尺寸正确，正负点与取消检查通过。
- HTTP 1280×720真实5帧：首次端到端30.32秒（其中加载5.43秒、分割24.69秒），中间帧补点重新传播28.08秒；全部帧有非空掩码。
- 马赛克/模糊/黑块三份实际导出均完整解码5帧；预览与编码输出均值像素差2.14、2.41、2.42。接口非法参数、缺少结果、缓存图像尺寸、失败恢复等回归通过。

这些是五帧短样本，不能据此外推实时性能、长片内存或遮罩全片准确率。官方预测器内部仍将帧缩放至模型尺寸，输入缩小不等于按比例加速。

## 原生界面验证

真实WebView2共21项检查通过：导入不推理、画布比例与点击原始坐标、正负点/撤销/负点帧限制、忙时锁定、真实传播、5帧掩码叠加、处理后JPEG、导出下载与5帧完整解码、补点同步清除旧处理结果。浏览器错误0。首轮验证脚本跨两次JS调用检查瞬时状态发生竞态，修正为同一次指针事件快照后完整重跑通过，产品页面未因该问题改动。

证据：runtime/native-verification/evidence.json；样例runtime/native-verification/native-export.mp4和runtime/acceptance三份视频。

## 观察与局限

单个正点可能圈出整个人或更大区域，而不只是点击处的脸。一次补点后掩码面积也可能大幅改变。现有机器工具无法直接向当前模型展示图片，因此未作人工目视分割质量结论；提供样例视频供你打开核对。当前结论是点击、传播、补点及导出链路可运行，尚不是隐私保护效果验收。

CPU每帧约数秒，适合短片试验，不能作为随点随动的实时体验。后续若继续集成，可先考虑图像编码缓存、先生成当前帧交互结果再传播，以及更短的目标区间；本次未擅自接入正式时间线。

数据留在本目录runtime；跨重启最多5段目录、每段5次传播和5份导出；3GiB为任务前软阈值，进行中的任务可能超过。无自动清理用户数据。
